## 统一采集架构采纳（2026-11-25）

采纳调研的统一 Ingestion Contract。主动记录与外部导入共用来源、原件、输入版本、规范化和幂等规则，原始资料、解析结果与可编辑笔记分别保存。处理阶段保留版本且允许重跑，重新解析不自动覆盖用户正文，索引任务可重建。首阶段不接 AI，连接器、Chunk 与向量索引后续建设。

实施顺序为统一采集基础、Markdown 与附件、URL、ChatGPT 导出、DOCX/PDF 解析验证。替代此前把导入整体放在 CRUD 之后的工程拆分。具体适配范围与验收依赖解析验证，见 [统一采集架构](../architecture/ARCHITECTURE.md)。原收集箱取消、系统归属建议需确认等规则继续有效。


## 记录与组织规则（2026-11-20 已确认）

- 取消收集箱及中转流程。保存后直接进入全部记录，可立即阅读、编辑与搜索。
- 填写时减少必填项，允许只写正文。位置与标签可留空，未分类不自动形成待办。
- 一个位置入口承接空间和分类；在目录内创建沿用当前已选择的位置。标签支持多个。
- 系统继续承担识别、整理和关联辅助。系统建议的位置与标签经用户确认后应用，候选不直接写入正式归属。
- 建议集中展示，支持批量确认、修改或忽略。具体分组、数量与提示频率待设计。
- 用户主动选择的位置和标签直接保存。思考脉络新成员及长期记忆仍各自按规则确认。
- AI 对话是内容来源之一。普通笔记阅读本身成立，不要求每条记录都提炼、关联或产生新记录。
- 原型尚未同步上述改版。旧 inbox / organized 状态的迁移、候选建议的数据结构及具体阶段待设计。


## 1. 路线图概述

灵脑的长期产品方向是知识管理、个人第二大脑与个人 AI 助手三者融合。路线图将这一方向拆解为可逐步交付的阶段，避免第一版同时承担所有长期愿景。

### 1.1 产品演进路径

| 阶段 | 产品能力 | 核心结果 |
|---|---|---|
| Phase 0 | 产品与工程准备 | 方向、范围、设计和技术方案明确 |
| Phase 1 | Studio 基础工作台 | 能够记录、编辑、组织和查找个人内容 |
| Phase 2 | 内容导入与知识关联 | 外部资料能够进入系统，内容之间能够建立联系 |
| Phase 3 | AI 知识助手 | AI 能够基于个人资料检索、回答并引用来源 |
| Phase 4 | Personal Memory | 逐步管理个人事实、经历、偏好、决策及其变化 |
| Phase 5 | Personal AI Assistant | AI 能够理解上下文，并在授权范围内辅助规划和执行 |
| Phase 6 | Automated Personal Brain | 逐步实现多来源自动采集、同步、整理和主动服务 |

这些阶段是能力成熟度划分，不代表必须等一个阶段的所有设想全部完成后才开始研究下一阶段。对于风险较低、验证价值高的能力，可以提前开展技术验证；正式进入下一阶段则需要满足相应的验收条件。

### 1.2 两条必须保持一致的采集决策

- **V1.0 实际目标：B——主动记录 + 外部导入。**
- **长期发展方向：C——尽可能自动化采集。**

V1.0 不以全平台自动同步为目标，但底层应保留来源、导入批次、外部标识和处理状态等必要信息，避免未来扩展自动采集时推翻内容模型。

### 1.3 AI 的推进原则

AI 是近期产品方向，不是路线图末尾才考虑的附加功能。

- 内容模型和基础 API 稳定后，尽早验证 LLM 辅助能力；
- 在内容导入、权限和来源链路可用后，尽早验证 RAG；
- RAG 有可靠的检索与引用基础后，再建设长期 Memory；
- Memory 的读取、写入和纠错机制稳定后，再扩大 Agent 的执行权限。

**先验证 AI 能否可靠利用个人资料，再逐步提高自主程度。**

---

### 本轮讨论的阶段约束（2026-11-16）

- 产品规则以 [PRD 7.2、7.14](PRD.md) 为准：首页向安静的思想动态档案演进，V1.0 无关联证据时展示最近记录，不伪造 AI 结果。
- 接入优先方向：AI 对话与日常随记优先，工作项目记录其次，再扩展外部资料；具体格式与交付拆分仍需评审。
- V1.0 保留可靠记录、人工组织与关联基础；独立思考脉络及人工时间线是否纳入、纳入哪个里程碑，待确认。
- 后续 AI 阶段验证主题发现、候选关联、经确认的长期记忆、带引用的梳理及候选版本更新。未确认候选不能作为正式记忆、正式成员或当前梳理版本。
- Agent 围绕积累的个人上下文完成实际任务，不以多一个聊天入口作为验收结果；首个验证任务与指标待确认。

Phase 编号以本路线图为准；V1.0 实际交付按 PRD 的 M0 → Alpha → Beta → Release 执行，不将概念阶段视为额外发布承诺。

## 3. Phase 1｜Studio 基础工作台

**阶段目标：建立可日常使用的私人知识工作台，打通内容创建、编辑、保存、组织和查找的基础闭环。**

这是灵脑第一个可运行版本的核心。

### 3.1 产品范围

#### A. 工作空间与基础框架

- Studio 主框架；
- 左侧导航和工作区切换；
- 个人账户与登录；
- 私人内容的访问控制；
- 全局搜索入口；
- 快速创建入口；
- 基础设置。

#### B. 全部记录与快速记录

- 快速创建内容；
- 保存后直接出现在全部记录；
- 支持稍后补充分类和标签；
- 支持草稿与已保存状态；
- 能够查看、编辑和删除自己的记录。

#### C. 知识空间与动态分类

- 创建、重命名和删除知识空间；
- 创建多级分类；
- 调整分类层级和位置；
- 将内容移动到其他空间或分类；
- 支持标签；
- 不将工作、学习、生活等领域写死为不可修改的结构。

#### D. 内容编辑

- 富文本编辑；
- Markdown 快捷输入；
- Markdown 源码编辑与预览；
- 标题、段落、列表、引用、链接、代码块和表格；
- 图片和附件；
- 自动保存或明确的保存状态；
- 基础内容版本或修改时间记录。

MDX 的安全渲染和组件扩展应在本阶段完成技术方案与原型验证。若完整 MDX 编辑会明显影响 V1.0 交付，可先交付受控 MDX 的存储、预览或发布链路，再逐步完善可视化组件编辑。不得将任意 JSX 当作可信内容直接执行。

#### E. 内容检索

- 标题和正文关键词搜索；
- 按空间、分类和标签筛选；
- 分页或渐进加载；
- 搜索结果能够打开对应内容；
- 删除、归档和移动后的结果保持一致。

#### F. 基础数据管理

- 私人内容默认不可公开；
- 内容创建者和权限检查；
- 内容与分类结构解耦；
- 关键数据具备稳定 ID；
- 基础数据导出能力；
- 删除和恢复策略明确。

### 3.2 关键用户流程

**流程一：快速记录**

打开 Studio → 快速创建 → 输入内容 → 保存到全部记录 → 后续整理。

**流程二：建立知识体系**

创建知识空间 → 创建分类 → 创建或移动内容 → 添加标签 → 通过导航浏览。

**流程三：编辑与查找**

打开内容 → 编辑 → 保存 → 全局搜索 → 筛选 → 再次打开。

### 3.3 阶段验收

- [ ] 用户能够创建、编辑、保存、查看和删除内容；
- [ ] 用户能够创建和维护动态知识空间及分类；
- [ ] 内容可以先进入全部记录，不要求创建时完成分类；
- [ ] 富文本编辑和 Markdown 基础能力可用；
- [ ] 自动保存状态明确，刷新或重新登录后内容仍然存在；
- [ ] 搜索能够找到已保存的标题和正文；
- [ ] 内容移动或分类调整不会破坏内容本身；
- [ ] 私人内容不能被未授权用户访问；
- [ ] 用户能够导出自己的基础内容数据。

**阶段结果：Studio Alpha，可完成个人知识记录和管理的基本闭环。**

## 4. Phase 2｜内容导入与知识关联

**阶段目标：让已有资料能够进入灵脑，并让不同内容之间形成可管理的联系。**

本阶段继续完成 V1.0 的主要知识积累能力。

### 4.1 外部内容导入

V1.0 采集方式为主动记录 + 外部导入。导入能力按可验证性分批交付。

| 来源 | 计划能力 | 交付策略 |
|---|---|---|
| Markdown / TXT | 导入正文、标题和基础元数据 | 优先支持 |
| DOCX | 提取正文和基础结构 | 验证解析效果后支持 |
| PDF | 提取文本并保留原文件 | 优先保证可用性；复杂版式后续完善 |
| 图片及附件 | 保存原文件、名称、类型和关联内容 | 支持附件管理；OCR 后续评估 |
| 网页链接 | 保存 URL、标题和可获取正文 | 先支持手动保存；复杂站点解析逐步完善 |
| ChatGPT 对话 | 导入官方导出数据，保留对话和消息关系 | 先验证真实导出样本，再确定首批格式 |
| 其他 AI 平台 | 根据实际导出格式扩展 | 不承诺首版覆盖所有平台 |

导入功能需要考虑：

- 导入任务状态；
- 失败原因和重试；
- 重复内容识别；
- 原始文件保留；
- 来源平台和来源地址；
- 导入时间；
- 导入后的内容归属；
- 导入内容的隐私默认值。

不应把“文件上传成功”直接视为“内容已正确导入”。需要分别验证文件接收、解析、入库和用户可查看结果。

### 4.2 来源与内容溯源

逐步建立统一来源信息：

- 来源类型：手动创建、文件导入、网页、AI 对话等；
- 原始文件或原始 URL；
- 来源平台；
- 来源记录 ID（如可获得）；
- 导入批次；
- 创建时间和导入时间；
- 内容处理状态。

原始来源与用户后续编辑内容应当能够区分。解析或 AI 摘要不能覆盖唯一的原始资料。

### 4.3 知识关联

- 手动关联两条或多条内容；
- 内容详情展示关联内容；
- 双向引用或反向链接；
- 解除关联；
- 关联类型和备注可按实际需求逐步增加；
- 关联关系独立存储，不依赖正文中的硬编码分类路径。

知识图谱可先作为关联数据的可视化，不应先建设复杂图谱引擎再补基础关联能力。

### 4.4 Site 基础发布

Site 是公开展示空间，不是私人 Studio 的镜像。

本阶段建立最小发布链路：

- 内容草稿、预览和发布状态；
- 用户明确选择发布；
- 公开文章详情；
- 基础公开列表或主页；
- 撤回发布；
- 服务端公开权限校验；
- 私人内容与公开内容隔离。

公开发布必须由用户主动触发。AI 总结、内容关联或导入操作不能自动改变公开状态。

### 4.5 阶段验收

- [ ] 支持的文件能够上传、解析并生成可查看内容；
- [ ] 导入失败能够显示状态和原因；
- [ ] 原始文件或原始来源得到保留；
- [ ] 网页保存能够保留原始 URL；
- [ ] ChatGPT 导入基于真实导出样本完成验证；
- [ ] 内容之间能够手动建立和解除关联；
- [ ] 内容详情能够查看关联内容；
- [ ] 用户能够明确预览、发布和撤回公开内容；
- [ ] 未发布内容无法通过公开页面访问；
- [ ] 导入和发布操作不会绕过用户权限。

**阶段结果：Luma V1.0，具备个人知识积累、组织、检索、关联和基础公开展示能力。**

## 5. Phase 3｜AI 知识助手

**阶段目标：让 AI 能够利用灵脑中的个人资料回答问题，并提供可核对的来源。**

AI 验证应尽早启动。内容模型和基础 API 稳定后，即可开展 LLM 技术验证；当导入、权限和来源链路具备条件后，接入真实个人资料进行 RAG 验证。

### 5.1 LLM 辅助能力

优先从低风险、高频场景开始：

- 内容摘要；
- 长文提炼；
- 改写和润色；
- 内容分类建议；
- 标签建议；
- 关联内容建议；
- 基于当前文档的问答。

AI 生成的结果应允许用户预览、修改和决定是否保存。

### 5.2 RAG 知识检索

逐步实现：

- 文档解析与分块；
- Embedding 生成；
- 向量检索；
- 关键词检索；
- 混合检索和结果排序；
- 检索结果与原文关联；
- 基于检索内容生成回答；
- 回答引用来源和片段；
- 用户权限过滤。

PostgreSQL 与 pgvector 可以作为候选实现方向，但具体索引、分块和检索策略应通过实际数据验证，不为技术选型本身增加复杂度。

### 5.3 评测与质量控制

建立小规模、可维护的个人知识评测集，至少覆盖：

- 是否检索到相关资料；
- 是否遗漏关键来源；
- 回答是否有资料支持；
- 引用是否指向正确内容；
- 无资料时是否明确说明；
- 私人资料是否发生越权检索。

先建立可重复的基础评测，再逐步完善自动化评测体系。

### 5.4 阶段验收

- [ ] AI 能够针对用户指定的个人资料进行问答；
- [ ] 回答能够展示对应来源；
- [ ] 用户能够打开来源并核对原文；
- [ ] 检索过程遵循用户权限；
- [ ] 无可靠依据时能够说明不确定或资料不足；
- [ ] 用户能够反馈错误回答；
- [ ] 核心检索与回答质量有可重复的测试样例。

**阶段结果：Luma AI Knowledge Assistant，可基于个人资料提供有来源依据的知识问答。**

## 6. Phase 4｜Personal Memory

**阶段目标：从检索个人文档，逐步发展为管理个人事实、经历、偏好、决策及其变化。**

Memory 不等于把所有文档向量化，也不等于让模型在每次对话中自动保存所有内容。

### 6.1 记忆类型逐步建设

可逐步研究和支持：

- 个人事实；
- 长期偏好；
- 目标与计划；
- 工作和学习经历；
- 项目经验；
- 重要事件；
- 个人决策及其依据；
- 观点和认知变化；
- 人物与关系上下文。

这些类型不要求一次性实现为复杂独立模块。应先验证哪些记忆类型有稳定使用价值。

### 6.2 记忆生命周期

每条重要记忆应尽可能具备：

- 内容；
- 来源；
- 发生时间或有效时间；
- 记录时间；
- 置信或确认状态；
- 关联对象；
- 当前状态；
- 修改和失效记录。

建议区分：

1. 原始资料：用户保存的文档、消息和记录；
2. 用户确认的记忆：用户明确认可的信息；
3. AI 推断：模型根据资料提出的候选结论；
4. 已失效或已被更新的信息：保留历史，不静默覆盖。

### 6.3 用户控制机制

- 查看 AI 提取的记忆；
- 确认或拒绝候选记忆；
- 修改记忆；
- 删除记忆；
- 查看记忆来源；
- 处理相互矛盾的信息；
- 查看记忆的更新时间和有效状态。

### 6.4 阶段验收

- [ ] 记忆能够关联原始资料；
- [ ] AI 推断与用户确认信息能够区分；
- [ ] 用户能够确认、拒绝、修改和删除记忆；
- [ ] 新旧信息冲突时不会静默覆盖；
- [ ] 能够基于时间和来源召回记忆；
- [ ] AI 使用记忆时能够展示依据；
- [ ] 用户能够管理记忆的访问和使用范围。

**阶段结果：Luma Personal Memory，形成可追溯、可纠正、可管理的个人记忆层。**

## 7. Phase 5｜Personal AI Assistant

**阶段目标：让 AI 不只回答问题，还能基于个人上下文辅助规划、思考和执行。**

### 7.1 助手能力

- 基于个人知识和记忆的持续对话；
- 跨领域信息汇总；
- 学习计划和项目辅助；
- 历史决策回顾；
- 个人目标进度分析；
- 多步骤任务规划；
- 工具调用；
- 用户授权后的任务执行。

### 7.2 Agent 执行原则

Agent 能力按风险分级：

| 级别 | 行为 | 控制要求 |
|---|---|---|
| L0 | 查询、检索、总结 | 遵循数据权限 |
| L1 | 生成草稿、提出建议 | 用户审核后保存 |
| L2 | 修改灵脑内部内容 | 明确授权，可撤销或恢复 |
| L3 | 调用外部服务或执行外部操作 | 每类操作单独授权，重要操作二次确认 |

不应为了展示 Agent 能力而提前赋予其不必要的外部操作权限。

### 7.3 阶段验收

- [ ] 助手能够调用经授权的个人知识和记忆；
- [ ] 多步骤任务能够展示计划和执行状态；
- [ ] 高风险操作需要用户确认；
- [ ] 工具调用有日志和结果记录；
- [ ] 失败任务能够说明原因；
- [ ] 用户能够停止执行和撤销可撤销操作；
- [ ] Agent 不得绕过 Studio 的内容权限和公开规则。

**阶段结果：Luma Personal AI Assistant，能够在明确权限范围内辅助用户思考和执行。**

## 8. Phase 6｜Automated Personal Brain

**阶段目标：从主动记录和手动导入，逐步发展为多来源、可控的自动采集和个人信息处理系统。**

这是长期方向，不属于 V1.0 的交付承诺。

### 8.1 自动采集方向

根据实际使用需求逐步评估：

- 浏览器网页收藏和剪藏；
- 文件夹或云盘同步；
- 邮件和日历连接；
- AI 对话平台连接；
- 消息和语音入口；
- 外部应用 API；
- 用户授权的设备或应用数据。

不预设所有平台都能提供稳定 API，也不以未经授权的抓取方式作为长期方案。

### 8.2 自动处理方向

- 增量同步；
- 重复内容识别；
- 来源识别；
- 内容解析；
- 自动摘要和分类建议；
- 知识关联建议；
- 记忆候选提取；
- 处理失败重试；
- 变更和删除同步。

### 8.3 自动化控制

- 用户可以单独启用或停用数据源；
- 明确展示连接权限；
- 允许查看采集记录；
- 允许暂停、断开和删除连接数据；
- 自动整理与原始内容分离；
- 重要记忆和公开操作继续受用户控制。

### 8.4 阶段验收

- [ ] 自动采集来源和权限清晰；
- [ ] 支持增量同步或明确的重复处理策略；
- [ ] 采集失败可观察、可重试；
- [ ] 原始内容和处理结果可区分；
- [ ] 用户能够暂停和断开数据源；
- [ ] 自动化不会越过私人内容和公开内容的权限边界；
- [ ] 自动处理结果能够纠正和追溯。

**阶段结果：Luma Automated Personal Brain，逐步降低长期信息采集与整理成本。**

## 11. 范围管理规则

为避免产品范围不断膨胀，新增需求必须经过以下判断：

1. 是否直接解决当前阶段的核心问题？
2. 是否存在成熟方案可以借鉴或复用？
3. 是否会改变已经确定的数据模型或权限边界？
4. 是否会阻塞当前阶段的核心闭环？
5. 是否可以推迟到后续阶段，而不影响当前价值？

### 11.1 需求处理原则

- 当前阶段必须项：纳入当前迭代，并明确验收标准；
- 有价值但非阻塞：记录到后续阶段；
- 仅因竞品拥有而提出：先研究用户价值，不直接加入；
- 技术探索项：先做小规模验证，不默认进入产品范围；
- 超出长期定位：暂不纳入。

### 11.2 路线图调整原则

路线图允许调整，但调整应记录：

- 调整原因；
- 影响的阶段和交付物；
- 对 PRD、产品决策和技术架构的影响；
- 是否需要重新评估验收标准。

不得通过随意增加功能来替代阶段目标，也不得为了追求进度跳过权限、数据可靠性和基础验收。
