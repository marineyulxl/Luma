## 2. 产品定位、目标与场景

Luma 是个人知识收集、整理、关联与学习管理工具。围绕“快速记下—归类—建立关联—主动学习—再次找到”形成闭环。V1 面向个人使用，以桌面浏览器为主要工作界面；不预设团队协作、公共发布或商业化。

核心用户：积累工作资料、技术知识和学习笔记的个人。主要问题是资料分散、分类维护成本高、内容缺乏关联、学过与未学难以区分。

| 场景 | 用户行为 | 成功结果 |
|---|---|---|
| 突然有想法 | 在任意主页面点击快速收集 | 内容先保存到统一收集箱，无需先分类 |
| 整理资料 | 编辑内容、指定类型、选择树节点 | 一份内容可在稳定位置继续维护 |
| 连接知识 | 正文插入另一篇内容引用 | 目标页自动显示来源反向链接 |
| 学习推进 | 手动改变学习状态 | 列表可按状态筛选，进度可见 |
| 再次使用 | 搜索标题或正文并结合过滤 | 找到原内容，打开后可继续编辑 |

V1 成功以第 11 节验收用例全部通过为准；使用频率、留存率等业务指标先不设未经验证的数值目标。

## 3. 功能优先级与 MVP

P0 是最小闭环及 Release 阻断项；P1 是 V1 完整体验，Release 前完成；P2 明确延期，不得因实现方便混入。

| 优先级 | 能力 | 范围 |
|---|---|---|
| P0 | 内容与收集箱 | 新建、查看、编辑、保存、归档收集箱项 |
| P0 | Tiptap 混合编辑 | 富文本操作及常用 Markdown 输入快捷方式 |
| P0 | 动态分类树 | 节点增改、移动、删除；内容归类 |
| P0 | 双向链接 | 按稳定 ID 引用，来源可追溯 |
| P0 | 类型、学习状态 | 元数据编辑及组合过滤 |
| P0 | 搜索 | 标题与正文关键词检索 |
| P0 | 数据可靠性 | 持久化、保存反馈、错误与冲突处理 |
| P1 | 回收站 | 删除、恢复、永久删除及确认 |
| P1 | 整理效率 | 树拖拽、列表分页、搜索结果摘要 |
| P1 | 基础可用性 | 键盘操作、空态、加载态、窄屏可操作 |
| P2 | 延后 | AI、Agent、自动总结、推荐、复习算法、间隔重复 |
| P2 | 延后建议 | 团队共享、实时协作、知识图谱可视化、浏览器扩展、离线同步、附件管理、批量导入 |

MVP = P0；Alpha 达到 MVP；Beta 补齐 P1 并验证可靠性；Release 达到全部 V1 验收。学习状态只是手动标记，不产生复习日期或自动学习任务。

## 4. 信息架构与页面

以下路由为建议设计，可由架构规格统一调整，但不可遗漏对应用户能力。

全局框架：左侧导航包含收集箱、全部内容、分类树、学习视图、回收站；顶部包含搜索与快速收集。中间列表、右侧或独立详情编辑区。主入口默认收集箱；选择内容与返回列表需保留当前过滤条件。

| 页面/路由 | 内容与关键交互 | 空态与异常 |
|---|---|---|
| 收集箱 `/inbox` | 未完成整理的内容，按创建时间倒序；快速创建、打开、选择分类、完成整理 | 空态提供新建入口；失败保留输入 |
| 全部内容 `/items` | 标题、类型、分类、状态、更新时间；类型/状态/分类过滤，可清空 | 无内容与筛选无结果分开提示 |
| 分类 `/categories/:id` | 当前节点及后代内容；切换仅当前节点；创建子分类、重命名、移动 | 节点不存在提示并返回全部内容 |
| 内容详情 `/items/:id` | 标题、Tiptap 正文、分类、类型、学习状态、保存反馈、反向链接 | 不存在与已删除有明确提示；未保存时阻止无提示离开 |
| 搜索 `/search?q=` | 输入词、筛选器、结果标题和纯文本摘要；点击进入原内容 | 空关键词不发检索；无结果提示；请求失败可重试 |
| 学习 `/learning` | 以学习状态过滤的内容列表，手动切换状态 | 不展示算法推荐或复习倒计时 |
| 回收站 `/trash` | 删除时间、恢复、永久删除 | 永久删除二次确认；恢复失败不移除行 |

快速收集弹层：标题可空、正文必有非空白文本；提交中禁用重复按钮；成功关闭并提示，失败保留全部输入。标题空时显示“未命名”，不据标题判断记录唯一性。

## 5. 编辑器与关联交互

混合编辑定义为同一 Tiptap 编辑器支持可视化工具栏和 Markdown 风格输入快捷方式，不要求 V1 提供完整 Markdown 源码双向编辑。支持段落、H1—H3、粗体、斜体、列表、任务列表、引用、代码块、外部链接、内部引用；附件与复杂表格暂不纳入建议范围。

正文以 Tiptap JSON 为权威源，纯文本投影用于搜索；禁止将纯文本反向覆盖原始格式。服务端校验文档结构、链接协议与长度，不信任粘贴 HTML；不执行用户脚本。

输入 `[[` 可搜索存量内容并插入引用，也可通过工具栏完成；Esc 关闭候选，Enter 选择。候选不含回收站内容，重名项显示分类和 ID 辅助区分。V1 不因输入不存在的标题自动创建内容。

引用保存目标 ID，目标改名后显示新标题；反向链接由正文引用派生，用户不能单独维护。重复引用同一目标只产生一条来源列表项。移除最后一次引用后来源消失。自引用允许，但不列入自身反向链接；环形引用允许。

建议自动保存：停止输入 1 秒后提交，另提供显式保存；页面展示“有未保存更改 / 保存中 / 已保存 / 保存失败”。只有服务端成功响应才显示已保存。失败可重试，不能清空编辑内容；有待保存内容时关闭/切换页面提示用户。

## 6. 核心对象及一致性规则

| 对象 | 最小产品字段 | 约束 |
|---|---|---|
| 内容 Item | ID、标题、正文 JSON、纯文本、分类 ID、类型 ID、学习状态、收集箱标记、创建/更新时间、版本号、删除时间 | ID 稳定；标题允许重名；创建时间不可被编辑覆盖 |
| 分类 Category | ID、名称、父 ID、同级顺序 | 单父树；不得形成循环；同一父节点下名称唯一 |
| 类型 Type | ID、名称 | 建议固定为笔记、资料、想法；默认笔记；类型与分类独立 |
| 引用 Link | 来源 ID、目标 ID | 由正文在同一事务更新，无重复边 |

建议单篇内容属于零或一个分类，未分类以空值表达；不将“未分类”作为可删除的普通节点。分类树是用户动态维护的层级，不是 AI 自动分类或复杂规则引擎。节点移动保留 ID 和内容归属；展开状态属于界面状态。

收集箱与分类相互独立：快速收集默认 `inbox=true`；选择分类不自动移出；点击“完成整理”后设为 false，允许未分类完成整理；提供“移回收集箱”。不通过移动或复制创建第二份内容。

学习状态建议固定为“未开始 / 学习中 / 已掌握 / 暂缓”，默认未开始，任意状态可手动互转；状态变化不改分类和正文，不触发复习算法。

建议限制：标题 200 字符、分类名 50 字符、分类深度 8 层、正文 JSON 序列化后 1 MiB；前后端使用相同校验与明确错误提示。具体上限须在 M0 确认，不宣称是历史决策。

## 7. 核心业务流程

1. 收集：打开快速收集 → 输入内容 → 提交 → 后端创建唯一记录 → 出现在收集箱 → 可立即打开；连续点击只创建一次。
2. 整理：打开收集箱项 → 修改类型/分类/正文 → 保存成功 → 点击完成整理 → 从收集箱消失，全部内容和分类视图仍可找到。
3. 关联：编辑 A 引用 B → 保存 A → B 的反向链接出现 A → 点击回到 A；删除引用再保存后同步移除。
4. 学习：搜索或选择分类 → 打开内容 → 手动标记学习中/已掌握 → 学习视图及列表同步显示。
5. 找回：输入关键词 → 服务端检索标题和正文纯文本 → 组合类型/状态/分类过滤 → 分页 → 打开内容。
6. 删除恢复：内容移入回收站 → 正常列表和搜索不可见 → 恢复 → 保持原 ID、正文、类型和状态；分类不存在则恢复为未分类。

## 8. 异常、边界与数据安全

- 分类移动：禁止移入自身或后代；超深度拒绝；失败后界面回滚。拖拽同时提供菜单移动入口。
- 分类删除：建议仅允许删除无子节点且无有效内容的节点；有内容时引导迁移，有子节点时先处理子节点。禁止静默级联删除笔记。
- 内容删除：软删除后其出链不参与有效反向链接，恢复后重新生效；其他内容对它的引用显示“已删除内容”，保留引用 ID。永久删除后显示“目标不存在”，不得误指向同名新记录。
- 永久删除：明确告知不可在应用内恢复并二次确认；只清理被删内容及其出链，不擅自修改其他正文。
- 编辑冲突：提交携带版本号；旧版本请求被拒绝，保留本地内容并提示重新加载/复制草稿；禁止静默最后写入覆盖。
- 网络异常：新建/修改结果不确定时先核对请求 ID 或版本；服务端新建支持幂等请求标识，重试不生成重复记录。
- 搜索：建议大小写不敏感、去除首尾空白，按连续关键词子串匹配；标题命中优先，其次更新时间、ID 稳定排序。中文至少支持子串；不承诺语义搜索。过滤器之间 AND；默认排除已删除，分类默认含后代。分页每页 20，最大 100。
- 多页加载：改变查询或过滤时回到第一页；忽略迟到的旧请求响应，避免结果串页。
- 安全：仅允许安全链接协议；所有接口服务端校验。公开网络部署前必须落实认证与数据隔离，不能默认无鉴权上线。
- 时间：数据库统一保存 UTC，界面按用户时区显示；排序以服务端时间为准。
- 备份：Release 前提供 PostgreSQL 备份与恢复步骤并实际演练；应用回收站不能替代备份。

## 9. 技术边界与非功能要求

固定技术栈：React 19 + TypeScript、FastAPI、PostgreSQL、Tiptap。数据库是内容及元数据的持久化来源，浏览器缓存不能作为唯一副本。数据迁移必须可重复执行并有回滚或恢复方案；正文、引用、搜索投影的更新保持事务一致性。

建议接口能力包括内容 CRUD、完成整理、状态变更、分类树 CRUD/移动、类型枚举、关键词检索、反向链接、回收站恢复及永久删除。API 路径、表结构、鉴权和部署方式另写架构规格，本文不冒充已完成技术设计。

建议质量目标：在约定测试机器与本地网络、10,000 篇内容和 500 个分类数据下，列表和搜索接口 p95 ≤ 1 秒、保存接口 p95 ≤ 1 秒；不含网络传输与 1 秒防抖。M0 记录硬件、正文大小分布、并发数和测试方法后才作为发布门槛。

桌面支持 Windows 上当前稳定版 Edge/Chrome；窄屏至少能收集、搜索与编辑，不要求原生 App。主要操作可用键盘，焦点可见；状态反馈不只依赖颜色。日志记录请求关联信息及错误，默认不记录完整正文或敏感内容。

## 10. M0 待确认与实施顺序

下列建议不能冒充历史结论。M0 必须把结果回写本文，避免开发者自行猜测：

| 决议 | 当前建议 | 影响 |

## 11. 可测试验收标准

下列验收涉及的建议规则，以 M0 最终决议为准；调整时同步改用例，不允许实现与文档分叉。

| ID | 操作与前置条件 | 预期结果 |
|---|---|---|
| AC01 | 空库打开收集箱；创建一条有正文、无标题内容 | 空态有入口；创建一条未命名记录，刷新仍存在 |
| AC02 | 快速收集提交纯空白；连续点击有效提交 | 空白被阻止；有效提交仅创建一条 |
| AC03 | 编辑标题、列表、引用、代码块后保存并重新打开 | 文本、结构、格式保持一致，显示已保存 |
| AC04 | 保存时断网，再恢复并重试 | 提示失败且输入保留；重试成功，无重复记录 |
| AC05 | 建 A/B/C 分类，将 B 移至 C 下，再尝试将 C 移入 B | 合法移动持久化；循环操作被拒绝且原树不变 |
| AC06 | 给收集箱内容设分类，再完成整理 | 分类后仍在收集箱；完成后仅从收集箱移除 |
| AC07 | 切换类型与四种学习状态，刷新并组合过滤 | 元数据保留；结果同时满足全部过滤条件 |
| AC08 | A 两次引用 B，B 改名；A 移除全部引用并保存 | B 仅一条来源 A；改名链接有效；移除后来源消失 |
| AC09 | 建立自引用和 A↔B 环形引用 | 编辑与导航正常，无无限递归；自身不列入反向链接 |
| AC10 | 标题和正文分别含中文关键词，含一条已删除记录 | 两种命中都可找到，标题优先；删除项排除；分页无重复 |
| AC11 | 删除内容后恢复，再永久删除其目标 | 删除项仅在回收站；恢复 ID 不变；永久删除须确认，旧引用显示缺失 |
| AC12 | 删除有内容/子节点的分类 | 操作阻止，明确提示先迁移或处理子节点，无内容丢失 |
| AC13 | 两个窗口基于同一版本编辑并依次保存 | 后一次旧版本请求报冲突，本地内容仍可复制 |
| AC14 | 输入超长标题/正文、粘贴脚本及危险协议链接 | 前后端一致拒绝超限；脚本不执行，危险链接不可执行 |
| AC15 | 访问不存在的内容/分类；模拟接口失败与无搜索结果 | 分别提供明确提示、返回入口或重试，不展示假成功 |
| AC16 | 备份后新增/修改测试数据，在独立数据库恢复备份 | 原备份数据、分类和引用可正常打开，记录恢复结果 |
| AC17 | 在约定数据与环境重复运行性能用例 | 达到第 9 节已确认门槛，保留样本量与 p95 记录 |
| AC18 | 键盘完成新建、保存、搜索、打开、分类菜单移动 | 焦点可见、无键盘陷阱；窄屏主要操作可达 |

## 12. 里程碑与退出条件

无承诺日历日期，以退出条件推进。存在未决范围时不以“代码写完”替代验收。

| 阶段 | 交付 | 退出条件 |
|---|---|---|
| M0 | 校对来源、关闭第 10 节决议；架构/API/模型规格；实施任务及测试环境 | 每项决议有记录；P0 可拆分；账号、存储、删除规则无歧义 |
| Alpha | P0 MVP：收集、编辑、分类、类型、关联、搜索、学习状态 | AC01—10、AC13—15 对应 P0 用例通过；人工走通收集到学习闭环 |
