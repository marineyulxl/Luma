## 记录与组织规则（2026-11-20 已确认）

- 取消收集箱及中转流程。保存后直接进入全部记录，可立即阅读、编辑与搜索。
- 填写时减少必填项，允许只写正文。位置与标签可留空，未分类不自动形成待办。
- 一个位置入口承接空间和分类；在目录内创建沿用当前已选择的位置。标签支持多个。
- 系统继续承担识别、整理和关联辅助。系统建议的位置与标签经用户确认后应用，候选不直接写入正式归属。
- 建议集中展示，支持批量确认、修改或忽略。具体分组、数量与提示频率待设计。
- 用户主动选择的位置和标签直接保存。思考脉络新成员及长期记忆仍各自按规则确认。
- AI 对话是内容来源之一。普通笔记阅读本身成立，不要求每条记录都提炼、关联或产生新记录。
- 原型尚未同步上述改版。旧 inbox / organized 状态的迁移、候选建议的数据结构及具体阶段待设计。


## 1. 战略摘要

灵脑的长期方向选择 **D：知识管理工具、个人第二大脑与个人 AI 助手三者融合**。

三者不是三个独立产品的简单拼接，而是一条逐步演进的产品路径：

- **知识管理工具**：建立可靠的信息收集、编辑、组织、搜索和关联能力。
- **个人第二大脑**：持续积累个人的知识、经历、思考、决策和偏好，使内容形成可追溯的个人上下文。
- **个人 AI 助手**：在用户授权范围内调用这些知识与记忆，提供检索、分析、辅助思考和任务执行能力。

灵脑以个人知识工作台为起点，以个人第二大脑为核心定位，以 AI 助手为长期能力延伸。

### 核心价值与闭环澄清（2026-11-16）

灵脑源于记录分散、长期容易混乱的真实困扰。核心价值包括快速复现知识，以及将零散的人生思考联系起来，回看经历、观点与选择的变化，在当下判断时调用过去的积累。长期理解覆盖用户愿意留下的生活、思想、学习与成长，不声称完整还原一个人。

产品闭环：自由记录 → 发现联系 → 用户确认 → 有依据地理解与回顾 → 辅助思考和任务 → 新经历与反思再次沉淀。Agent 是利用个人上下文完成任务的重要未来能力，其价值需由真实任务验证。首页定位为安静的个人思想动态档案，避免统计大屏与消息推送中心。

具体确认机制、权限、思考脉络及阶段边界统一维护于 [PRD 7.14](PRD.md)（以章节标题为准）。

### 1.1 战略选择

| 战略问题 | 当前决策 |
|---|---|
| 长期产品形态 | D：知识管理 + 个人第二大脑 + 个人 AI 助手融合 |
| 核心产品定位 | 个人数字第二大脑 |
| 第一阶段落地形态 | A：个人知识管理工作台 |
| 核心价值 | 积累、组织、关联、找回和利用个人知识与记忆 |
| V1.0 信息采集 | B：主动记录 + 外部导入 |
| 长期信息采集 | C：尽可能自动化采集 |

| 首要用户 | 个人所有者，先以真实自用验证 |
| 产品形态 | 私人 Studio + 公开 Site |

### 1.2 一句话定义

**灵脑是一个能够持续积累、组织、关联和调用个人知识与记忆的数字系统，并逐步通过 AI 理解个人上下文，辅助用户思考与行动。**

## 2. 愿景、使命与产品承诺

### 2.1 产品愿景

成为个人长期使用的数字第二大脑，让一个人在不同阶段积累的知识、经历、思想和决策能够持续保存、建立联系，并在未来重新发挥价值。

### 2.2 产品使命

降低个人信息沉淀和知识管理的成本，帮助用户把分散的信息转化为有组织、可追溯、可复用的个人知识与记忆。

### 2.3 核心产品承诺

灵脑希望持续做好四件事：

1. **收得进来**：让用户能够低成本记录，也能够导入已有资料。
2. **组织得起来**：允许用户按照自己的方式组织内容，不被固定分类体系限制。
3. **找得回来**：能够通过搜索、关联和 AI 检索重新找到过去的信息。
4. **用得起来**：让历史知识、经验和思考能够在新的工作、学习和生活场景中发挥作用。

灵脑不承诺替代人的真实记忆，也不承诺 AI 永远正确。系统应当提供可核对、可纠正、可管理的信息支持。

## 3. 要解决的核心问题

个人在工作、学习和生活中持续产生大量知识、资料、经历、想法和决策，但这些内容往往分散在聊天记录、文档、网页、笔记工具和个人设备中。随着时间推移，内容难以找回，经验难以复用，个人上下文也难以延续。

灵脑聚焦以下五类问题：

| 核心问题 | 典型表现 | 灵脑的解决方向 |
|---|---|---|
| 信息分散 | 文件、网页、聊天和笔记分布在不同位置 | 统一收集与导入 |
| 记录和整理成本高 | 记录前需要决定放在哪里、如何分类 | 快速记录、先收集后整理、动态组织 |
| 知识彼此孤立 | 不同领域的内容缺少联系 | 标签、双向链接、关系和上下文 |
| 历史经验难以复用 | 过去的项目、问题和决策无法及时调用 | 来源追踪、搜索、关联和历史召回 |
| AI 缺少个人上下文 | 每次对话都需要重新解释背景 | RAG、Memory 和个性化 AI 助手 |

### 3.1 核心价值不是“保存更多”

灵脑不以笔记数量、附件数量或知识图谱节点数量作为最终价值。

真正需要验证的是：

- 用户能否更容易找回过去保存的信息？
- 用户能否重新利用过去的经验和决策？
- 内容之间的联系是否能帮助用户理解当前问题？
- AI 是否能基于真实、相关、可追溯的个人资料提供更有用的回答？
- 使用时间越长，产品是否越能提供持续价值？

## 4. 目标用户与切入市场

### 4.1 长期目标用户

灵脑长期面向有持续知识积累和个人上下文管理需求的人，包括但不限于：

- 程序员、工程师、产品经理和设计师；
- 研究人员、知识工作者和专业人士；
- 自由职业者、内容创作者；
- 长期学习者和有系统记录习惯的个人。

这些用户的共同特征不是职业相同，而是持续产生并希望长期利用自己的知识、经验和思考。

### 4.2 初期切入用户

初期不追求覆盖所有人，先以**个人所有者本人**作为第一位真实用户。

以真实使用过程验证：

- 工作项目和技术经验是否能持续沉淀；
- 学习资料和学习过程是否容易组织和回顾；
- 生活记录、个人思考和重要决策是否能与其他内容共存；
- AI 对话和外部资料能否顺利进入灵脑；
- 过去积累的内容能否在新的问题中被重新利用。

### 4.3 用户范围原则

灵脑不将“工作”作为唯一中心，也不预设一套不可修改的人生分类。

工作、学习、生活、兴趣、经历、思考和规划都属于个人信息积累的合理范围。用户可以自行创建知识空间、分类、标签和内容类型。

### 4.4 当前不以商业化为前提

现阶段首先验证个人长期使用价值，不急于确定订阅价格、获客渠道或商业模式。

未来若扩展为面向其他用户的产品，再通过真实用户研究验证共性需求、使用频率和付费意愿。

## 5. 产品定位与竞争策略

### 5.1 定位选择

灵脑不是单纯的 Markdown 笔记网站，不是另一个 Notion，也不是只提供 RAG 问答的 AI 知识库。

灵脑的核心定位是：

**个人数字第二大脑：围绕一个人的知识、经历、思考和决策，建立长期可积累、可关联、可追溯、可被 AI 调用的个人上下文系统。**

### 5.2 竞品策略：学习成熟能力，不复制产品边界

灵脑不因为竞品已经具备某项功能就拒绝建设该功能。成熟产品已经验证的基础能力，应当优先研究、借鉴或复用。

| 参考产品 | 重点研究方向 | 灵脑的策略 |
|---|---|---|
| Notion | 工作空间、编辑器、页面组织、数据库和模板 | 借鉴成熟的信息组织与编辑体验 |
| Obsidian | Markdown、本地知识、双向链接和知识图谱 | 借鉴知识关联与数据可迁移理念 |
| AFFiNE | 文档工作台、白板和内容体验 | 研究工作台的信息架构与交互 |
| Mimir | 多渠道采集、AI 知识处理、RAG 和主动召回 | 研究自动采集与 AI 知识处理流程 |
| Blinko / Memos | 快速记录、全部记录、轻量搜索和自托管 | 研究降低记录成本的方式 |
| Capacities | 对象化知识组织 | 研究人物、项目、事件等对象关系 |

竞品研究不以功能数量为目标。每项能力需要判断：

- 直接吸收：成熟且符合灵脑定位的基础能力；
- 吸收并改进：能力有价值，但交互、组织方式或流程可以优化；
- 差异化探索：围绕灵脑的长期定位寻找更有价值的体验；
- 暂不采用：会显著扩大范围，或与核心价值关系不大的能力。

直接复用开源代码前，必须核对仓库当前许可证、依赖许可证、维护状态、安全风险和部署成本。不能仅凭项目介绍或 README 宣称就认定功能成熟或许可证允许任意复用。

### 5.3 灵脑的差异化假设

当前不宣称已经形成技术或市场护城河。以下方向是需要通过产品设计和真实使用持续验证的差异化假设。

#### 差异化方向一：跨领域的个人上下文

将工作、学习、生活、兴趣、经历和思考放在同一个可扩展的个人系统中，而不是让用户为每个领域维护一套互不相通的工具。

#### 差异化方向二：可追溯的个人记忆

不只保存 AI 总结出来的结论，还尽可能保留原始内容、来源、发生时间、记录时间、用户确认状态和后续变化。

#### 差异化方向三：知识与经历的持续利用

帮助用户把过去保存的资料、项目经验、历史决策和个人思考重新带入当前场景，而不只是返回一组相似文档。

#### 差异化方向四：用户主导、AI 辅助

用户拥有内容和记忆的控制权。AI 可以提出摘要、分类、关系和记忆建议，但重要信息的写入、修改、删除和公开应当遵循明确授权规则。

#### 差异化方向五：个人积累的时间复利

随着内容、关系和历史上下文逐渐积累，灵脑应当更容易帮助用户找回信息、理解变化和复用经验。内容数量增长本身不构成价值，能够持续改善用户体验才构成价值。

### 5.4 需要避免的差异化误区

以下内容单独来看都不足以构成灵脑的独特竞争优势：

- 使用 Next.js、FastAPI、PostgreSQL 或 pgvector；
- 接入某个大模型；
- 具备 RAG、知识图谱或 Agent；
- 支持 Markdown、MDX 或富文本；
- 同时提供私人后台和公开网站；
- 功能数量多于某个竞品。

这些属于技术选型、基础能力或产品形态。差异化必须最终体现在用户价值和实际体验上。

## 6. 核心产品架构

灵脑的产品能力围绕五个层次组织。

### 6.1 Capture｜信息采集

解决个人信息如何进入灵脑。

V1.0 采用“主动记录 + 外部导入”：

- 手动创建笔记、想法、经历和资料；
- 导入 Markdown、TXT、DOCX、PDF 等文件；
- 保存图片及其他附件；
- 保存网页链接及可提取正文；
- 导入 ChatGPT 等 AI 平台导出的对话记录，首批优先验证 ChatGPT 格式。

长期方向是 C：尽可能自动化采集，逐步接入外部应用、浏览器、消息和文件来源，支持增量同步与重复识别。

自动化采集必须尊重平台授权、用户隐私和来源规则，不以绕过访问限制为前提。

### 6.2 Organize｜知识组织

解决内容如何被用户理解和管理。

- 动态知识空间和多级分类；
- 标签和内容类型；
- 全部记录与待整理状态；
- 内容编辑、归档和版本管理；
- Markdown 导入导出；
- 富文本编辑；
- 受控 MDX 内容表达能力。

内容与分类结构解耦。用户可以先记录，再整理；调整分类不应破坏内容身份和既有引用关系。

### 6.3 Connect｜知识关联

解决不同内容之间如何建立联系。

- 手动建立内容关联；
- 双向链接和反向引用；
- 内容与项目、人物、事件和决策之间的关联；
- 时间、来源和上下文关系；
- 后续逐步引入自动关联建议和知识图谱。

自动生成的关系应当能够查看依据、纠正或删除，不能把 AI 推断直接当作已确认事实。

### 6.4 Intelligence｜智能理解

解决 AI 如何利用个人知识和记忆。

近期优先能力：

- LLM 辅助总结、解释、改写和整理；
- RAG 个人知识检索与问答；
- 回答引用原始内容或资料来源；
- AI 分类和关联建议；
- 基础评测，检查检索相关性、回答依据和引用准确性。

后续逐步发展：

- Memory：个人事实、偏好、经历、决策和变化的识别、确认、更新与召回；
- Agent：在用户授权范围内调用工具、规划步骤和执行任务；
- 主动服务：在适当场景下发现相关历史知识、提醒用户或提出建议。

AI 能力是近期产品方向，不应被无限推迟到所有知识管理功能完成之后。基础数据流程稳定后，应尽快开展 AI 能力验证。

### 6.5 Experience｜产品体验

通过统一的产品体验承载以上能力：

- Studio：私人创作、知识管理和 AI 工作空间；
- Site：用户主动选择发布的公开知识展示空间；
- AI 助手：逐步融入搜索、编辑、整理和知识使用流程。

## 7. 产品形态与体验策略

### 7.1 Studio｜私人工作空间

Studio 是灵脑优先建设的核心界面，承担：

- 快速记录和统一收集；
- 知识空间与分类管理；
- 内容编辑、预览和附件管理；
- Markdown 与受控 MDX 内容创作；
- 导入、搜索、标签和知识关联；
- 私人内容管理和发布控制；
- 后续 AI 助手与记忆管理。

Studio 借鉴 Notion 等成熟产品的工作台体验，但不追求复刻其全部功能。优先保证记录、编辑、整理、查找和复用的连续性。

### 7.2 Site｜公开展示空间

Site 用于展示用户主动发布的内容：

- 公开首页；
- 公开知识分类和内容列表；
- 文章详情和阅读体验；
- 公开搜索；
- 公开内容之间的安全关联。

Site 不是私人 Studio 的简单只读镜像，也不是通用网站搭建器。它应当提供独立、完整的阅读体验。

### 7.3 两个空间的关系

- Studio 是内容的创建和管理源头；
- Site 只展示用户明确发布的内容；
- 私人内容默认不公开；
- 内容被整理、被 AI 处理或被建立关联，不代表同意发布；
- 撤回公开内容后，匿名访客不应继续访问其正文。

### 7.4 编辑与内容表达策略

灵脑需要兼顾日常记录与高级内容创作：

- 富文本编辑：默认日常编辑体验；
- Markdown：标准内容格式、源码编辑、导入导出和迁移；
- MDX：用于受控的高级内容表达，尤其是技术文章和可嵌入交互组件的公开内容。

MDX 不等于允许任意 JSX 在服务器或浏览器中执行。应采用受控组件白名单和安全渲染策略。富文本结构、Markdown 和 MDX 是不同的数据表示方式，格式转换需要明确支持范围，不能承诺任意内容无损互转。

## 8. 产品原则与决策约束

以下原则用于指导 PRD、UI/UX、数据库、API 和研发决策。

### 8.1 个人优先

产品围绕一个人的完整知识和经历设计，不局限于职业、工作或某一种知识领域。

### 8.2 用户定义组织结构

分类、空间和标签应动态创建。系统可以提供默认模板，但不能强制用户使用固定的人生领域目录。

### 8.3 先收集，再整理

不让分类和元数据成为记录的前置门槛。允许内容先进入全部记录，再逐步完善。

### 8.4 内容与组织结构解耦

内容应有稳定身份。分类调整、空间移动和标题修改不应破坏内容关联。

### 8.5 来源与时间可追溯

尽可能保留原始来源、原始文件、来源平台、发生时间、记录时间和处理记录。发生时间与录入时间应在数据语义上区分。

### 8.6 用户拥有数据

支持可读、可迁移的导出格式。避免个人知识被锁定在无法迁移的专有结构中。

### 8.7 隐私默认优先

私人内容默认私有。公开发布需要明确操作。AI 使用数据也必须遵循权限和授权边界。

### 8.8 AI 可解释、可纠正、可控制

AI 应尽可能提供来源依据；区分原始事实、用户确认信息和模型推断；重要记忆的新增、修改和删除应允许用户查看与控制。

### 8.9 可靠性优先于自动化程度

自动采集、自动整理和 Agent 执行必须建立在可追踪、可撤销、可恢复的基础上。不能为了自动化而牺牲数据可靠性。

### 8.10 避免功能堆砌

每项新功能都应回答：它是否降低信息沉淀成本？是否改善知识组织和找回？是否帮助用户利用个人积累？如果都不是，就不应仅因竞品拥有该功能而加入。

## 9. 产品路线与阶段目标

本章按能力概述长期方向，不使用下列编号安排研发任务；正式 Phase 编号以 ROADMAP 为准，V1.0 里程碑以 PRD 为准。

产品路线按能力成熟度推进。各阶段可以并行研究，但交付顺序应控制复杂度。

### Phase 1｜Studio 基础工作台（V1.0）

**目标：建立可靠的个人知识管理基础。**

范围：

- 登录与私人权限；
- Studio 基础框架；
- 全部记录和快速记录；
- 知识空间、动态分类和标签；
- 内容创建、编辑、保存、删除和归档；
- 富文本和 Markdown 基础能力；
- MDX 受控内容能力的设计与安全边界；
- 文件、网页和 AI 对话导入；
- 基础搜索和知识关联；
- 内容来源追踪；
- 数据导出；
- Site 的基础发布链路和公开阅读能力。

信息采集决策：

- V1.0：B，主动记录 + 外部导入；
- 长期：C，尽可能自动化采集。

### Phase 2｜AI 知识助手（近期启动）

**目标：让个人知识能够被 AI 检索和利用。**

优先能力：

- LLM 辅助；
- RAG 个人知识问答；
- 来源引用；
- 内容摘要和整理建议；
- 基础评测；
- 检索权限隔离。

该阶段目标窗口是 V1.0 核心数据流程稳定后的近期迭代，当前预期约为一至两个月，具体以实际开发和验证情况为准，不作为固定发布日期承诺。

### Phase 3｜Personal Memory

**目标：从检索文档逐步发展为理解个人历史上下文。**

优先研究和实现：

- 个人事实、偏好、经历和决策；
- 发生时间与认知变化；
- 记忆提取、确认、纠正和失效；
- 记忆与原始来源关联；
- 历史上下文召回；
- 冲突信息处理。

### Phase 4｜Personal AI Assistant

**目标：让 AI 能够基于个人知识和记忆提供持续帮助。**

逐步实现：

- 个性化 AI 对话；
- 跨知识领域分析；
- 学习和工作辅助；
- 历史决策复盘；
- Agent 工具调用；
- 多步骤任务规划与执行；
- 用户授权和执行确认。

### Phase 5｜Automated Personal Brain

**目标：降低长期信息采集和管理成本。**

逐步探索：

- 外部应用连接器；
- 自动采集与增量同步；
- 去重和来源识别；
- 自动内容处理；
- 主动发现关联；
- 主动召回与提醒；
- 可控的个人工作流自动化。

自动化不等于无条件自主。用户始终需要能够查看来源、管理权限、暂停连接和纠正结果。

## 10. 成功标准与验证方法

灵脑不以功能数量、代码规模或知识图谱规模作为成功标准。

### 10.1 V1.0 产品验证

| 指标 | 验证问题 |
|---|---|
| 记录完成率 | 用户能否低成本保存新内容？ |
| 导入成功率 | 常见文件、网页和 AI 对话能否进入系统？ |
| 整理完成率 | 用户是否能够按自己的方式组织内容？ |
| 找回成功率 | 用户能否通过搜索找回过去的内容？ |
| 关联使用情况 | 用户是否实际使用内容关联？ |
| 数据可迁移性 | 用户能否导出并理解自己的数据？ |
| 隐私正确性 | 私人内容是否始终受到权限保护？ |

### 10.2 AI 阶段验证

| 指标 | 验证问题 |
|---|---|
| 检索相关性 | 是否找到真正相关的个人资料？ |
| 回答依据正确性 | 回答是否得到检索资料支持？ |
| 引用准确性 | 用户能否打开并核对原始来源？ |
| 记忆准确性 | 是否区分事实、推断和用户确认信息？ |
| 记忆纠错能力 | 用户能否修正、删除或更新错误记忆？ |
| 任务执行可靠性 | Agent 是否遵循权限并正确完成任务？ |

### 10.3 长期价值验证

核心问题是：

**使用时间越长，灵脑是否越能帮助用户找回历史知识、理解个人变化，并在新的场景中复用过去的经验？**

如果内容持续增长，却没有改善找回、理解和复用体验，就不能认为产品已经形成时间复利。

## 11. 当前不做什么

为了保证战略聚焦，当前不把以下事项作为核心建设目标：

- 不复刻完整 Notion、Obsidian 或 AFFiNE；
- 不把灵脑做成通用团队协作平台；
- 不建设社交社区、关注和内容流；
- 不在 V1.0 实现完整多 Agent 系统；
- 不一开始接入所有外部平台；
- 不把 AI 自动分类和自动写入作为默认行为；
- 不把任务、日历、财务等成熟垂直产品全部纳入；
- 不以知识图谱可视化作为产品的主要价值；
- 不为了技术先进而提前引入复杂基础设施；
- 不在缺少用户验证时宣称已经形成市场护城河。

这些事项未来可以重新评估，但必须证明与灵脑核心价值有关。

## 12. 关键风险与应对策略

| 风险 | 可能后果 | 应对策略 |
|---|---|---|
| 产品范围不断膨胀 | V1.0 长期无法交付 | 坚持阶段边界和验收标准 |
| 与成熟竞品高度重合 | 用户没有迁移理由 | 聚焦个人上下文、可追溯记忆和经验复用 |
| 信息采集成本过高 | 用户无法持续使用 | 先收集后整理，逐步增加导入和自动采集 |
| AI 生成错误记忆 | 用户失去信任 | 来源追踪、用户确认、纠错和版本记录 |
| 私人内容泄漏 | 严重损害产品可信度 | 服务端权限检查、默认私有、公开数据隔离 |
| RAG 回答不可靠 | AI 无法真正帮助用户 | 建立评测集、来源引用和失败反馈 |
| 过度依赖单一模型 | 成本、质量和供应商风险 | 模型适配层与可替换设计 |
| 过度借鉴开源项目 | 架构复杂或许可证风险 | 核对许可证、维护状态和真实代码质量 |
